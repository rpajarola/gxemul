Introduction:

A machine can be set up in three ways:

  1. Started without arguments, GXemul shows a window with your machines, where you can create machines, change them, and start them. (This needs a build with SDL, i.e. framebuffer windows.)
  2. A machine configuration file, machine.json, describes one machine. gxemul machine.json starts it, and gxemul --edit machine.json opens it in the window. General and debugging options (such as -q, -v, -V, or -i) can be given with it; options that describe the machine (such as -d or -M) cannot, since the file does that. gxemul --export machine.json folder makes a copy of the machine in a folder of its own, with copies of all its files (see Export).
  3. Everything on the command line, as before, e.g. gxemul -e 3max -d disk.img (see gxemul -h).

A configuration file describes one machine. Several machines are run as several GXemul processes, connected with their network settings (UDP ports and remote hosts), as in the diskless examples in the machine documentation.

(The older configuration file format, gxemul @configfile, is no longer supported.)


The machines window:

The window lists the machines used recently. Select one to see a summary of it, and:

  • New... opens a new machine in the editor.
  • Open... adds an existing machine.json to the list.
  • Edit opens the selected machine in the editor.
  • Duplicate makes a copy of it, as a new machine (it uses the same disk images, unless you change them).
  • Export... makes a copy of it in a folder of its own, with its files (see below).
  • Forget removes it from the list (its files are kept).
  • Settings... sets the folders where ROM images are looked for (see below).
  • Start starts it.

Export makes a self-contained copy of a machine, e.g. to move it to another computer, or to give it to someone: a folder with its machine.json, and the files it uses. For each file (the system ROM, option ROMs, files to load, drive images, and the NVRAM file), choose:

  • Copy: it is copied into the folder, and the copy is referred to by its name (disk images stay sparse). A file that is in the machine's own folder keeps its name there (e.g. disks/disk.img); another gets its own name, or another one, e.g. disk-2.img, if two files have the same name. A file that doesn't exist yet (e.g. the NVRAM file of a machine that hasn't run) is just named there.
  • Leave in place: the copy refers to it where it is: by its name, if it is a ROM image in a ROM folder (see below), or else by its full name (which may include your home folder's name).
  • Omit: it is left out: no ROM image, no medium in a CD-ROM or tape drive, or no such disk drive, floppy drive, or file to load.
The new machine is added to the list. Cancel stops the copying, and removes what was copied. Export... in the editor does the same for what is in the editor (also unsaved changes, once the machine has been saved), e.g. from a running machine's Edit Configuration... menu item: then its disk images and NVRAM may change while they are copied, so for a consistent copy, shut the guest down first (or at least sync its disks). gxemul --export machine.json folder does the same from the command line, copying every file.

The editor has a page for each part of the configuration: General (name, architecture, machine type and model, memory, CPU), Firmware (a system ROM image and the option ROM images of the TURBOchannel cards, or PROM emulation with files to load and the boot file name and argument, and the NVRAM file, with a button to reset it), Drives (disks, CD-ROMs, tapes, and floppies; on a DECstation, a drive can be one of DEC's, e.g. an RZ26 disk, which a new disk image gets the size of, or say it is any other drive; missing disk images can be created with a given size), Display (the framebuffer window, its size, the number of graphics cards, and serial ports on telnet ports), Network, and Advanced. The line above the buttons says what's missing before the machine can be started. Save writes the file, and creates the disk images that are missing; Save and Start also starts the machine. The first time a new machine is saved, a file chooser asks where: the name given is a folder for the machine (with its machine.json, and its new disk images), or, if it ends in .json, the configuration file itself. File choosers start in the folder used last. Escape or Cancel leaves the editor without saving.

The machine is chosen on the General page, with an architecture (MIPS, PowerPC, ...), a machine type of that architecture (e.g. DECstation/DECsystem), and a model, if the type has models (e.g. DECstation 5000/200). Only the models known to work are offered: the DECstations 3100, 5000/200, and 5000/1xx, the SGI O2, and the MIPS test machine. Show all machines also offers the others, which may not work. A new machine starts as a DECstation 5000/200, and until it is saved, choosing another model gives it that model's defaults (memory, drives, firmware, and display). A new DECstation runs a real system ROM image, chosen on the Firmware page; with PROM emulation (a checkbox there), no ROM image is needed, and gxemul boots a kernel itself, from a drive or from files to load.

A running machine's window has these menus:

  • Machine: Save Screenshot, Record Video, Enter Debugger, Reset (starts the machine again, as if it was switched off and on), Edit Configuration... (for a machine started from a configuration file), and Quit.
  • View: the window's size: Fit the Screen, Actual Size, Half Size, or Double Size.
  • Media: Load... and Eject, for each CD-ROM and tape drive.

A running machine started from a configuration file has Edit Configuration... in its window's Machine menu. This opens its configuration in the editor, in a window of its own, while the machine keeps running; the changes take effect when the machine is started again.

File names can be typed or chosen with Browse..., which uses the desktop's file chooser. Text fields are edited at the end (backspace and typing), and Ctrl+V (Command+V on macOS) pastes.


Where machines and settings are kept:

A machine is usually a folder with its machine.json, and its disk images. File names in machine.json are relative to its folder, unless they are absolute. When it is saved, a file in its folder (or below it) is kept relative to it, so the folder can be moved or copied as a whole, and other files by their absolute names. New machines are saved in ~/GXemul (Documents\GXemul on Windows), unless another place is chosen.

ROM images (the "rom" and "slots" files) given by a relative name are looked for in the machine's folder, then in the common ROM folder, ~/GXemul/ROMs by default, and then in other folders. These are set with Settings... in the machines window. A ROM image in one of these folders is kept by its name relative to that folder, so several machines can use the same ROM images, wherever they are.

The list of recently used machines (recent.json), and the settings (settings.json: the ROM folders, and the folder last used in a file chooser) are kept in:

  • macOS: ~/Library/Application Support/gxemul/
  • Windows: %APPDATA%\gxemul\
  • Others: $XDG_CONFIG_HOME/gxemul/, or ~/.config/gxemul/


The machine.json format:

A machine.json is a JSON object with a "gxemul" key (the format version, 1). Every other key is optional, and has the default shown here, except for the machine type: 

{
  "gxemul": 1,
  "name": "My DECstation",
  "machine": {
    "type": "decstation",       the machine type and model, as for -E and -e
    "model": "3max",            (see gxemul -H)
    "cpu": "",                  "" = the machine's default
    "cpus": 0,                  0 = 1
    "memory_mb": 0,             0 = the machine's default
    "emulated_hz": 0,
    "byte_order": "",           "", "big", or "little"
    "random_memory": false,
    "random_bootstrap_cpu": false,
    "serial_nr": 0              0 = automatic
  },
  "boot": {
    "prom_emulation": true,     false = run a real ROM (as -Q)
    "rom": "",                  the system ROM image (loaded at 0xbfc00000 on DECstations)
    "load": [],                 other files to load, e.g. "netbsd" or "0xbfc00000:rom.bin"
    "bootname": "",             as -j
    "bootarg": null,            as -o; null = the default
    "netboot": false,           as -O
    "start_paused": false,
    "nvram": "",                a file for the RTC's NVRAM (the firmware's settings), "" = not kept
    "skip_failing_tests": false load copies of known ROMs whose tests that fail in gxemul pass
  },
  "drives": [
    { "file": "disk.img",       "" for a CD-ROM or tape drive without a medium
      "kind": "disk",           "disk", "cdrom", "tape", or "floppy"
      "bus": "default",         "default", "scsi", or "ide"
      "id": -1,                 the SCSI ID, -1 = the next free one
      "readonly": false,
      "overlay": false,         writes go to a temporary overlay (as the R prefix of -d)
      "boot": false,
      "vendor": "",             what a SCSI drive says it is (INQUIRY), "" = the usual:
      "product": "",              e.g. "DEC", "RZ26     (C) DEC", "T386" (up to 8, 16,
      "revision": "" }            and 4 characters)
  ],
  "display": {
    "enabled": false,           framebuffer windows (as -X)
    "scale": 0,                 the window size in percent (e.g. 50, 100, 200), 0 = fit the screen
    "cards": -1                 graphics cards, -1 = the default (as -Z)
  },
  "serial": { "telnet": false },  serial ports on telnet ports (as -x; on with the framebuffer)
  "slots": { "0": "PMAG-BA.bin" },  option ROM images, by TURBOchannel slot (see the 5000/200's slots 5 and 6)
  "network": {
    "enabled": true,
    "ipv4": "10.0.0.0",
    "ipv4len": 8,
    "local_port": 0,            a UDP port for connecting emulators, 0 = none
    "remotes": [],              e.g. "localhost:12345"
    "tapdev": "",               as -L: a host interface to bridge to (e.g. "en0"), or a tap device
    "mac": "",                  the first NIC's Ethernet address, "" = from the serial number
    "l2tp": { "enabled": false, "session": 1, "cookie": "", "counter": true }
  },
  "devices": []                 extra devices, as for the debugger's device add
}

(The comments in blue are not part of the file: JSON has no comments.)


A minimal example:

This starts NetBSD/pmax from a disk image in the same directory, on an emulated DECstation 5000/200, with PROM emulation and a framebuffer: 

{
  "gxemul": 1,
  "name": "NetBSD/pmax",
  "machine": { "type": "decstation", "model": "3max", "memory_mb": 64 },
  "boot": { "bootname": "netbsd" },
  "drives": [ { "file": "netbsd-pmax.img", "kind": "disk", "id": 0 } ],
  "display": { "enabled": true }
}

And this runs the real ROM of a DECstation 5000/1xx, with the option ROM image of a PMAG-BA framebuffer in slot 0, and a CD-ROM to install from: 

{
  "gxemul": 1,
  "name": "DECstation 5000/133",
  "machine": { "type": "decstation", "model": "3min", "memory_mb": 32 },
  "boot": { "prom_emulation": false, "rom": "decstation5000_133.bin" },
  "drives": [ { "file": "disk.img", "kind": "disk", "id": 0 },
              { "file": "ultrix-4.5.iso", "kind": "cdrom", "id": 4 } ],
  "display": { "enabled": true },
  "slots": { "0": "PMAG-BA_V5.3a.bin" }
}
