GXemul: DECpc AXP 150 / DEC 2000 Model 300 ("Jensen") emulation

Back to the index.

The DECpc AXP 150 (also known as the DEC 2000 Model 300 AXP, code-named "Jensen") was Digital Equipment Corporation's first PC-class Alpha system, introduced in May 1993. Unlike the workstation-oriented DEC 3000 family which used TURBOchannel, the Jensen combined Digital's high-performance 64-bit Alpha RISC microprocessor with an industry-standard EISA (Extended Industry Standard Architecture) bus and standard PC peripherals.

GXemul emulates the complete Jensen motherboard and expansion subsystem:

  • DECchip 21064 (EV4) 64-bit Alpha RISC microprocessor running at 150 MHz.
  • EISA Bus Logic featuring full sparse address mapping:
    • Sparse EISA memory space (0x200000000) and sparse EISA I/O space (0x300000000).
    • Dense EISA memory space (0x3f0000000).
    • Hardware Address Extension (HAE) register for dense access to arbitrary EISA memory banks.
    • Hardware system control logic: SYSCTL, LED/switch registers, and INTA interrupt vector generation.
  • Adaptec AHA-1742A EISA SCSI Host Adapter in Slot 1:
    • Enhanced 32-bit Mode with Mailbox In/Out communication protocol.
    • Enhanced Command Block (ECB) execution with scatter-gather physical bus master DMA.
    • Target inquiries, read/write commands, and SCSI bus device identification.
    • Selectable edge- or level-triggered EISA interrupts (IRQ 9, 10, 11, 12, 14, 15; as configured by the ECU; the factory NVRAM uses IRQ 14).
  • Compaq QVision 1024/E EISA graphics controller in Slot 2 (with the display on; see below):
    • VGA with 1 MB of four-plane video memory, all write and read modes, text, 16- and 256-colour modes.
    • QVision extended registers (unlock, chip ID, banking), the DAC extension registers, and the EISA board ID CPQ3011.
    • The packed 8-bit modes, the linear framebuffer, and the BitBLT engine as Windows NT's QV.DLL uses it.
    • The card's own x86 option ROM at C0000, which the ARC console runs to set up the card.
  • DEC DE422 EtherWORKS Turbo EISA Ethernet controller in Slot 3 (with networking on; see below): the AMD LANCE with 64 KB of buffer RAM, the DEPCA registers, the Ethernet address ROM and the EISA board ID DEC4220.
  • Intel 82357 Integrated System Peripheral (ISP):
    • Dual cascaded 8259 interrupt controllers (PIC) delivering PC and EISA IRQs.
    • 8254 programmable interval timer (PIT).
    • Dual 8237 DMA controllers, with the 82357 EISA extensions (high page, high count and extended mode registers).
  • Super I/O and System Peripherals:
    • Dual 16550A compatible UARTs (COM1 serial console at 0x3f8, COM2 at 0x2f8).
    • Parallel printer port (LPT1 at 0x3bc).
    • Standard 8042 PS/2 keyboard and mouse controller.
    • MC146818 / DS1287 real-time clock and NVRAM.
    • Intel 82077AA floppy disk controller (0x3f0, IRQ 6, DMA channel 2), with a 3.5" 1.44 MB drive A: (-d f:image.img).
  • Flash ROM Subsystem:
    • 512 KB Flash ROM containing genuine Digital SRM console firmware or ARC console.
    • Embedded EISA Configuration Utility (ECU) non-volatile configuration memory (NVRAM Block 6).
    • Write protection logic protecting flash sectors while permitting NVRAM updates.

The following guest firmware and operating systems have been verified:

  • Configuration via machine.json — Graphical and JSON configuration files for Windows NT and OpenVMS.
  • Windows NT 3.1 Alpha (Build 528) — Genuine Digital ARC Multiboot console (Version 3.0.g); installs from scratch and boots to Program Manager on the emulated QVision.
  • Digital SRM Firmware ROM v1.3 — Passes 100% of power-up self-tests: CPU OK, MEM OK 64MB, NVR OK, SCC OK, IT OK, KBD OK, LPT OK, SCSI OK.
  • Compaq QVision 1024/E — The SRM console (power-up test VGA OK), the ARC console and the ECU run on the emulated display and PC keyboard; Windows NT 3.1 GUI-mode Setup runs to the end on it.
  • DE422 Ethernet — The power-up test passes (NI OK); Windows NT 3.1 detects the card, and TCP/IP works through GXemul's simulated network (ping, FTP to the Internet).
  • EISA Configuration Utility — Digital ECU V1.9 runs from a floppy diskette image through the ARC console, and saves its configuration.
  • OpenVMS AXP V1.5-1H1 — Full bootstrap via Adaptec AHA-1742A SCSI driver (SYS$PKJDRIVER) to Stand-alone BACKUP and interactive DCL prompt ($ ).
  • DEC OSF/1 AXP (in active development)


Configuration using machine.json:

A Jensen system is easiest to set up and run using a machine.json configuration file. You can create or edit one interactively using the graphical configuration window (gxemul without arguments, or gxemul --edit machine.json) by selecting Alpha in the Architecture menu and DECpc AXP 150 / DEC 2000 Model 300 in the Machine menu.

Windows NT 3.1 Setup Configuration (jensen_nt.json):

This configuration attaches the installation CD-ROM to SCSI ID 4, creates a hard disk image on SCSI ID 0, enables NVRAM ECU pre-population, and connects the serial console over telnet (port 4000):

{
  "gxemul": 1,
  "name": "Windows NT 3.1 (DECpc AXP 150)",
  "machine": {
    "type": "jensen",
    "model": "300",
    "memory_mb": 64
  },
  "boot": {
    "prom_emulation": false,
    "rom": "media/rom/jensen_v1_3.rom",
    "nvram": "nvram.bin",
    "populate_ecu": true
  },
  "drives": [
    { "file": "nt_disk.img", "kind": "disk", "id": 0 },
    { "file": "nt31_alpha.iso", "kind": "cdrom", "id": 4, "readonly": true }
  ],
  "serial": { "telnet": true, "vt100": true }
}

7-bit VT100 Translation: Digital ARC Multiboot 3.0.g natively outputs 8-bit DEC C1 control sequences (0x9b for CSI) and expects 8-bit CSI key sequences for arrow navigation (\x9bA..\x9bD). Modern terminal emulators (xterm, GNOME Terminal, Windows Terminal, macOS Terminal) expect standard 7-bit VT100/ANSI escape sequences (\x1b[). Setting "vt100": true (or command line option -7 / --vt100) enables bidirectional 7-bit VT100 translation:

  • Output: translates 8-bit C1 controls (0x80..0x9f, such as 0x9b → \x1b[) to standard 7-bit escape sequences, and translates CP437 box drawing characters to clean ASCII borders (+, -, |).
  • Input: translates host terminal 7-bit cursor sequences (\x1b[A..\x1b[D or \x1bOA..\x1bOD) to 8-bit CSI (\x9bA..\x9bD) so ARC Multiboot menus can be navigated cleanly with arrow keys.

Launch the emulator: 

	gxemul jensen_nt.json
and in another terminal, connect to the emulated COM1 console: 
	telnet localhost 4000

Windows NT 3.1 Alpha:

Windows NT 3.1 was Microsoft's first release supporting the 64-bit Alpha AXP architecture. On the DECpc AXP 150, Windows NT requires the Digital Advanced RISC Computing (ARC) firmware (ARC-Multiboot Alpha AXP Version 3.0.g) and a valid EISA Configuration Utility (ECU) table defining the Adaptec AHA-1742A SCSI host adapter.

ECU and NVRAM Pre-population:

By default, GXemul automatically pre-populates genuine factory NVRAM tables for the Jensen:

  • Block 6 (0x60000): EISA Configuration Utility (ECU) table configuring the Adaptec AHA-1742A host adapter in Slot 1 on IRQ 14, as saved by the real ECU V1.8 (the firmware programs INTDEF from it at boot).
  • Block C (0xc0000): ARC Configuration Tree (Section 1) and ARC Environment Variables (Section 2, including SYSTEMPARTITION, OSLOADER, CONSOLEIN, and CONSOLEOUT).
This pre-population avoids the "Invalid entry in NT Configuration tree" fatal error and NVRAM inconsistency warning boxes on boot.

The ARC and SRM consoles keep their settings (environment variables, configuration tree, boot selections and ECU data) in the Flash ROM. When an nvram file is configured, the whole Flash image is also kept, in <nvram file>.flash, so that these settings survive restarts. Once that file exists it is used instead of the rom image and of the pre-population below; delete it to start over from the factory state.

Pre-population can be configured via the populate_ecu setting:

  • In JSON configuration: "populate_ecu": true (or false to boot with raw unconfigured Flash ROM).
  • In the Configuration UI (-E): The "Pre-populate ECU and NVRAM configuration" checkbox.

Installing Windows NT 3.1 from scratch:

Windows NT 3.1 installs completely, through text-mode and GUI-mode Setup, and the installed system boots to the logon screen and Program Manager. NT 3.1 has no plain VGA driver for Alpha, so this needs the display and the emulated Compaq QVision (see below).

You need:

  • the Jensen firmware, media/rom/jensen_v1_3.rom (see below);
  • the Windows NT 3.1 for Alpha CD (build 528) as an ISO image;
  • an image of the QVision's option ROM, qvision.rom (see below), which the ARC console needs to use the screen;
  • a copy of Digital's ECU for Windows NT diskette (V1.8 has been tested; AlphaECUWNT1-10.ZIP also has one). Use a copy: the ECU saves to it, and Setup later writes the Emergency Repair Disk over whatever is in drive A:. The ECU for OpenVMS and Digital UNIX does not work for NT (see below);
  • an empty hard disk image, e.g. 500 MB: 
    	truncate -s 500M nt_disk.img

A machine.json for the installation (nt.json):

{
  "gxemul": 1,
  "name": "Windows NT 3.1 (DECpc AXP 150)",
  "machine": { "type": "jensen", "model": "300", "memory_mb": 64 },
  "boot": {
    "prom_emulation": false,
    "rom": "media/rom/jensen_v1_3.rom",
    "nvram": "nt_nvram.bin",
    "populate_ecu": true
  },
  "drives": [
    { "file": "nt_disk.img", "kind": "disk", "id": 0 },
    { "file": "nt31_alpha.iso", "kind": "cdrom", "id": 4, "readonly": true },
    { "file": "ecu_nt_copy.img", "kind": "floppy", "id": 0 }
  ],
  "display": { "enabled": true },
  "slots": { "2": "qvision.rom" }
}

With the nvram setting, the console's settings, the EISA configuration and the boot selections are kept in nt_nvram.bin.flash. Delete that file to start over from the factory state. Start the machine with gxemul nt.json. After the power-up tests, the ARC console's Boot menu appears on the screen; use the arrow keys and Enter.

  1. Create the system partition (first, before the ECU, see below). Choose Run a program and enter 
    	scsi(0)cdrom(4)fdisk(0)\alpha\arcinst
    In the Arc Installation Program, choose Configure Partitions, then Create Partition, and enter a size of 5 MB. The partition is created, formatted (FAT), and made the system partition. Choose Exit twice to get back to the boot menu.
  2. Configure the EISA cards. Choose Supplementary menu..., Set up the system..., and Run EISA configuration utility from floppy (the yellow item). The ECU starts from the diskette; press Enter at its first screen. Under Step 2: Add or remove boards, the ECU lists the Adaptec AHA-1742A in slot 1 and the QVision 1024/E in slot 2; press F10. Then choose Step 5: Save and exit, Save the configuration and restart the computer, and press Enter to restart. (Wait for each ECU screen before pressing the next key, see below.)
  3. Text-mode Setup. Choose Supplementary menu... and Install Windows NT from CD-ROM. At Welcome to Setup, press Enter, then Enter again for Express Setup.
    • In the list of hardware, Computer is Unknown: press Enter on it and choose DEC Alpha_AXP Personal Workstation. The display is already Compaq QVision, 640x480, 256 colors. Then select No Changes and press Enter.
    • Select the Unpartitioned Disk Space, press Enter, choose Format to FAT and confirm with F.
    • Accept \winnt as the directory. Setup copies the files and restarts into GUI-mode Setup.
  4. GUI-mode Setup runs on the QVision. Enter your name (Tab to the company field) and confirm, enter a computer name and confirm, and accept the language. With no printer, choose Cancel in Set up Local Printer. Without networking (the configuration above), there is no network card: choose Continue twice in Network Adapter Card Detection, then No Network (Tab to it) and OK; networking can be added later (see below). Set the Administrator password and, if you like, a local account, then accept the date and time. For the Emergency Repair Disk, the diskette in drive A: is erased and written. Setup ends with Windows NT 3.1 is now installed; choose Restart Computer.
  5. First boot. The boot menu now has Boot Windows NT Version 3.1. NT checks the disks and shows the logon screen. Press Ctrl+Alt+Del and log on.

Notes:

  • The system partition must be created before the ECU is run. Once the QVision is configured, ARC reserves its framebuffer (4–5 MB), and arcinst, which runs at 6 MB, stops with Failed to initialize the heap. If that happens, delete the .flash file, create the partition, and run the ECU again.
  • Image can't be relocated, no fixup information and ntoskrnl.exe is missing or corrupt mean that the QVision's "High Address Video Buffer" is at 1 MB, where NT's kernel has to be loaded. The OpenVMS/Digital UNIX ECU diskettes (e.g. Digital ECU Diskette V1.8 and V1.9 for OpenVMS and Digital UNIX) put it at 1, 2 or 3 MB; the Windows NT ECU (V1.8, V1.10, V1.11) at 4 MB or 20–31 MB. Delete the .flash file and configure again with the Windows NT ECU (in the ECU, Step 3: View or edit details shows the address). The installation on the disk is not affected.
  • Setup does not recognize the machine (Computer: Unknown) because the ARC console reports the system as DEC-00Jensen.
  • The date shows the year 2006.
  • There is no mouse pointer; use the keyboard. Ctrl+Alt+Del may be taken by the host's desktop; it can also be sent through the control socket (keyboard {"keys": ["Control_L+Alt_L+Delete"]}).
  • Now and then (about one boot in fifteen), GUI-mode Setup stops at the plain teal desktop: a deadlock in Windows NT's csrss. Restart the machine; Setup carries on.


Digital SRM Firmware ROM:

To run the genuine Digital Jensen SRM firmware in GXemul, pass -o vms (or -o srm): 

	gxemul -e jensen -x -M 64 -o vms media/rom/jensen_v1_3.rom

The CMOS register 0x4f (OS_TYPE) selects the boot console: 1 for Windows NT ARC Multiboot (default), 2 for OpenVMS SRM, and 3 for DEC OSF/1 SRM.

The SRM firmware initializes the hardware and performs full power-up diagnostics:

Networking: DEC DE422 EtherWORKS Turbo EISA:

With networking on ("network": { "enabled": true } in machine.json; GXemul's command line always has a network), the Jensen has a DE422 Ethernet controller in EISA slot 3, as it shipped. It is connected to GXemul's network (see the networking documentation): by default a simulated network 10.0.0.0/8, with a gateway and name server at 10.0.0.254 that passes TCP and UDP on to the host's network. The Ethernet address is random unless "mac" is set in the network section.

The factory NVRAM includes the DE422 when networking is on, so both consoles start without complaint, and the SRM power-up test shows NI OK. A machine whose .flash file was saved without the DE422 reports Slot(3) Missing Configuration; run the ECU from the ARC console again (Supplementary menu → Set up the system → Run EISA configuration utility from floppy) and save: it detects the Digital EISA Ethernet Controller (DE422-SA) in slot 3 and configures it with IRQ 5 and a 64 KB buffer at D0000.

Windows NT 3.1 drives the DE422 with its lance.sys (DEC EtherWORKS Turbo EISA Adapter). To add networking to an installed system, log on as Administrator and open Control Panel → Network. Answer Yes to install networking (the files come from E:\alpha\, the CD), choose Continue to detect the adapter; Setup finds the DEC EtherWORKS Turbo EISA Adapter. To use TCP/IP, choose Add Software and TCP/IP Protocol, then OK. NT 3.1 has no DHCP client: in TCP/IP Configuration, enter an IP address such as 10.0.0.1 (subnet mask 255.0.0.0) and the default gateway 10.0.0.254; for host names, enter 10.0.0.254 as the DNS server under Connectivity. Restart, and ping 10.0.0.254 or ftp to a host on the Internet from a command prompt.


Video console: Compaq QVision 1024/E:

With the display on (-X, or "display": { "enabled": true } in machine.json), the Jensen has a Compaq QVision 1024/E in EISA slot 2, as it shipped, and its PC keyboard is in use. Both consoles then use the screen and keyboard instead of the serial port. Without the display there is no video card, and the consoles use COM1 as before.

The SRM console programs the VGA itself. The ARC console instead runs the x86 BIOS from the card's option ROM, so it needs an image of that ROM, given for slot 2:

	"display": { "enabled": true },
	"slots": { "2": "qvision.rom" }

The image is 64 KB: the card's two 32 KB EPROMs (U40 and U21) interleaved, U40 holding the even bytes. It contains two banks of the BIOS, which the card switches with its EISA register zC85 (bit 4). To make one from two dumps:

	python3 -c 'import sys; a=open(sys.argv[1],"rb").read(); b=open(sys.argv[2],"rb").read(); \
	  open("qvision.rom","wb").write(bytes(x for p in zip(a,b) for x in p))' U40.bin U21.bin

Without the ROM image, ARC falls back to the serial console.

The factory NVRAM does not list the QVision, so at power-up the SRM console finds a new board and offers to run the ECU (Invoking Eisa Config Utility... Continue (Y/N)?), as a real machine does after a card is installed. Answer Y with an ECU diskette in drive A: and save the configuration (see below); the ECU finds the card by its board ID (CPQ3011, from ACPQ3011.CFG on the Digital ECU diskettes). With an nvram file, the configuration is kept. The ARC console uses the card either way.

For Windows NT, configure the card from the ARC console instead (Supplementary menu → Set up the system → Run EISA configuration utility from floppy), with the Windows NT ECU diskette:

  • Only an ECU run from ARC adds the display controller (identifier CPQ3011) to the ARC configuration tree, which is how NT Setup recognizes the QVision. Run from SRM, the ECU only updates the EISA configuration.
  • The OpenVMS/Digital UNIX ECU places the card's 1 MB "high address video buffer" at 1 MB. ARC then reserves host memory 1–2 MB, where the NT 3.1 kernel has to be loaded, and OSLOADER fails with Image can't be relocated, no fixup information and ntoskrnl.exe is missing or corrupt. The Windows NT ECU places it at 4 MB.

The Windows NT 3.1 driver (QV.SYS and QV.DLL, 640x480 with 256 colours) works: GUI-mode Setup draws and runs to Windows NT 3.1 is now installed. It uses the packed 8-bit mode, the linear framebuffer (at the EISA address in GC 48h/49h) and the BitBLT engine: fills with an 8x8 pattern, colour expansion of 1-bit glyphs, copies, and bitmaps that the CPU writes through the framebuffer. There is no documentation of the BitBLT engine; it is emulated as the driver uses it (see src/devices/dev_qvision.c).

What is not emulated yet: the hardware cursor (NT never sets a pointer shape, so no mouse pointer shows), the packed 4-, 15- and 24-bit modes, the line draw engine (83C0h), and the video interrupt (IRQ 9).


Running the EISA Configuration Utility (ECU) from floppy:

The ECU is an ARC program on a 1.44 MB floppy (e.g. the Digital "ECU for OpenVMS and Digital UNIX" or "ECU for Windows NT" diskette). Attach the diskette image as floppy drive 0 (A:) with the f prefix, or as { "file": "ecu.img", "kind": "floppy" } in machine.json. The ECU saves its configuration to the diskette, so use a copy of the image: 

	gxemul -e jensen -x -M 64 -d f:ecu_copy.img media/rom/jensen_v1_3.rom
  1. From the SRM console, enter runecu (or answer Y to the power-up ECU prompt) and press Return. The SRM firmware hands over to the ARC console. (Without -o vms, the machine starts in the ARC console directly.)
  2. In the ARC console, select Supplementary menu..., then Set up the system....
  3. ARC insists that the yellow items are done in order: first Set default environment variables, then Set default configuration (choose a 3.5" 1.44MB floppy drive, and no second floppy).
  4. Select Run EISA configuration utility from floppy. ARC saves NVRAM, restarts, and loads the ECU from the diskette.

The ECU's Step 5: Save and exit writes the configuration to the Flash NVRAM and a backup SYSTEM.SCI file to the diskette.

The ARC firmware drives the floppy controller in non-DMA (PIO) mode. The 82077 also implements DMA transfers through the 82357 DMA controller (channel 2), and checks that the data rate matches the medium, as the real chip does, which the firmware relies on to detect the disk type.

Typing ahead loses keys and can desynchronize the ECU: wait for each ECU screen to finish drawing before pressing the next key, and do not hold down the arrow keys. The ARC firmware's serial console Read reads ahead up to five bytes into a private buffer (to collect escape sequences), but its GetReadStatus only looks at the UART, not at that buffer. Before waiting for a key, the ECU discards typeahead with "while a key is available, read it". If a key arrives while the ECU is still busy, that loop reads the first byte of the arrow key's escape sequence and leaves the rest hidden in the firmware buffer. From then on every arrow key reaches the ECU one byte late, as a plain letter, and the menus appear to stop responding. Pressing a single-byte key once (such as a letter that the current screen ignores) gets back in step. This is firmware behaviour, and real hardware has the same flaw, but the emulator's lower speed makes the window for it much wider.


OpenVMS AXP 1.5-1H1:

OpenVMS AXP V1.5-1H1 includes native support for the DECpc AXP 150 and the Adaptec AHA-1742A SCSI adapter via the SYS$PKJDRIVER.EXE port driver.

To boot the OpenVMS AXP 1.5-1H1 installation media:

  1. Launch GXemul with the installation CD attached to SCSI ID 0:
    	gxemul -e jensen -x -M 64 -o vms -d 0:/path/to/openvms_axp_1.5-1H1_os.iso media/rom/jensen_v1_3.rom
  2. Connect to the serial console:
    In a separate terminal, connect to the emulated COM1 serial console: 
    	telnet localhost 4000
  3. Boot the CD-ROM from the SRM console:
    When prompted Continue (Y/N)?, press N. At the >>> prompt: 
    	>>> boot dka0
  4. OpenVMS Startup:
    The SRM console loads the Primary Bootstrap (APB), mounts the CD-ROM, and starts the executive: 
    	INIT-S-CPU...
	AUDIT_BOOT_STARTS ... 
	AUDIT_CHECKSUM_GOOD
	AUDIT_LOAD_BEGINS
	AUDIT_LOAD_DONE

	    OpenVMS AXP (TM) Operating System, Version V1.5-1H1  

	Please enter date and time (DD-MMM-YYYY  HH:MM)  07-NOV-2026 12:00
	%SAB$IOGEN-I-Beginning device autoconfiguration..
	Available device PKA0:  type WIDGET
	Available device DKA0:  type RRD42
	%BACKUP-I-IDENT, Stand-alone BACKUP V1.5; the date is  7-NOV-2026 12:00:03.31  
	$
    At the Stand-alone BACKUP prompt ($ ), OpenVMS is ready to restore savesets or inspect disks.


DEC OSF/1 AXP:

DEC OSF/1 AXP supports the DECpc AXP 150 hardware configuration with the Adaptec AHA-1742A EISA SCSI host adapter (aha0 driver). Support for booting DEC OSF/1 under GXemul is currently in active development.
